# Exploratory QA, 2026-10-06 (0.11.0 browser build)

Hands-on browser testing of the shared editor, done before the literal-bullet and Pure Ink changes in the same batch. Each finding below was reproduced again on the changed source, and none were caused or fixed by those changes. These are open findings, not fixes. Remaining work is tracked in the [roadmap](../ROADMAP.md).

**Status.** D1–D7, F1 and F2 were fixed later on 2026-10-06 (see the [changelog](../changelog.md)), with regressions in desktop/data-safety-smoke.cjs. The Formatted-view Outline scroll (scroll-position-smoke.cjs) and mouse access to Clear formatting under » (toolbar-smoke.cjs) were fixed on 2026-10-07. All other findings remain open.

**Method.** Headless Edge 154 with Playwright-core 1.63. Every scenario used a fresh, isolated browser context. Testers used real typing, keys, mouse selection and toolbar/menu clicks; note setup and paste events were scripted. For each check they recorded the DOM, the saved Markdown (`editor.value`) and the result after a reload.

**Not covered:** the desktop app's own interactions (the desktop suites passed), the real clipboard, a physical IME, touch, native pickers and physical printing.

Severity:
- **Data**: text or structure lost or corrupted in the saved Markdown.
- **Format**: formatting changes after a save, reload or view switch.
- **UX**: a caret, focus, visual or reachability problem; saved data is not affected.

## Data

| # | Reproduction | Actual result |
| --- | --- | --- |
| D1 | Type `one cat two cat three cat`, press Ctrl+F, type `cat`, then press Enter twice in the Find box (Formatted or Markdown view). | The first Enter moves focus into the editor with the match selected. The second Enter replaces `cat` with a line break, and the change is saved. Clicking ↓ and then typing does the same. Ctrl+Z restores the text. |
| D2 | `1. aaa` with nested `1. bbb` and `2. ccc`: select `bbb`..`ccc` (or only part of one nested item) and press Shift+Tab or Decrease indent. | The items merge into one: saved as `1. aaabbbccc`, and it stays merged after reload. Bullets do the same. |
| D3 | Type `1. aaa`, Enter, `bbb`, Enter, `ccc`; press Shift+ArrowUp, then Tab, then Ctrl+Z. | Saved as `1. aaa\n2. bbbccc`, which persists. |
| D4 | In a fenced code block, press Enter, Shift+Enter, or paste several lines. | The DOM gets `<br>`, but the code-block serializer uses `textContent`, so the line breaks are dropped from the Markdown. |
| D5 | In `- [ ] Alpha` / `- [ ] Beta`, press Backspace three times at the start of `Beta`. | Saved as `- [ ] Alpha☐Beta`; the checkbox glyph becomes literal text. |
| D6 | Clear formatting on the end of a bold word or on a whole line, or Replace all across a bold boundary. | Empty `<strong>`/`<a>` elements are saved as `****` or `[](url)` and reload as literal text. |
| D7 | Paste several lines into a brand-new blank Formatted note (known roadmap issue; broader than documented). | The first two lines are joined for any text, e.g. `FirstSecond\nThird`. It does not happen after Ctrl+A and Delete. |

## Format

| # | Reproduction | Actual result |
| --- | --- | --- |
| F1 | With automatic conversion off, type `# text` or `~~text~~` in Formatted view. | Shown as literal text, but saved unescaped, so it reloads as a heading or strikethrough. The Outline lists it immediately. |
| F2 | Type `notes.md`, `file.txt`, `node.js` or a missing-space typo such as `end.Next`. | Auto-linked, even with conversion off, and saved as `[notes.md](https://notes.md/)`. |
| F3 | Shift+Enter inside bold text. | Saved as `**bold\nnext**`, which reloads as two paragraphs with literal asterisks. |
| F4 | A bullet inside a quote, Quote on a list item, or Heading 1 on a list item. | Reloads as literal `- item`. |
| F5 | Insert a divider inside a list item. | Saved as `1. item***`; reloads as literal `***`. |
| F6 | Heading 2 (Paragraph style) applied to two selected paragraphs. | Becomes a single `<h2>one<br>two</h2>`; after reload only the first line is a heading. |
| F7 | Inline code containing a backtick. | Saved as `` `a`b` ``, which breaks on reload. |
| F8 | With conversion on, type `~~strike~~ after`, `==hi== after` or `` `code` after``. | The text typed after the closing marker continues inside the format. Bold, italic and underline exit correctly. |
| F9 | Link a bold selection with Ctrl+K. | The bold is dropped. |
| F10 | Ctrl+B, Ctrl+I, type, then toggle both off; or reopen `***text***` (known roadmap issue). | Literal asterisks appear after reload. |
| F11 | Inline code or Highlight with no selection. | Inserts the placeholder words `code` or `highlight`, attached to the previous word. |
| F12 | Checkbox list on two selected paragraphs or bullets, or with the caret on a line. | One task is created for all lines, or a new `Task` item is added below; existing lines are not converted. |

## UX

- **Clear formatting is unreachable by mouse in the browser build.** (Fixed 2026-10-07.) It lives under » at every width, and opening » clears the selection, which disables the button. There is no keyboard shortcut.
- **Bullet/Numbered list commands move the caret** to the start of the line.
- **Undo puts the caret in the wrong place** after marker removal, Tab or Bold.
- **Tab on a multi-item selection drops the selection.**
- **Task items:**
  - Enter at the end of a task puts the new checkbox after the text until reload.
  - The first Backspace at the start of a task's text does nothing visible.
- **Markdown view:** after Enter on an empty list marker, the caret returns to the end of the previous line.
- **Toggles:** Highlight never toggles off. Saved strikethrough cannot be removed. Quote and Inline code are not toggles.
- **Backspace-merging a heading or quote** into a paragraph leaves inline size or color spans.
- **Insert table** leaves the caret below the table and prefills the header with `Column 1..3`.
- **Outline:**
  - In Formatted view it scrolls only on the second click. (Fixed 2026-10-07.)
  - In Markdown and Split views, Outline and Find land on the wrong place when lines wrap.
- **Large pastes are slow.** Pasting 100/200/400 lines into Formatted view takes about 0.5 s, 1.8 s and 15 s, because every input re-serializes the whole note. Typing in a 2,000-line note takes about 150 ms per key.
- **Restoring a backup with display settings** replaces all preferences, including sort, split ratio, outline and auto-Markdown.
- **The backup file name uses the UTC date** (shows the previous day just after midnight in Manila).
- **Trashing the last note** creates a blank Untitled note each time, and these accumulate in Trash. There is no permanent delete or Empty Trash in the browser build.
- **Bold shows as pressed in headings.**
- **The Outline empty-state hint is wrong:** it mentions an H button that doesn't exist and `# ` conversion, which is off by default.
- **A note name can be saved blank.**
- **Keyboard trap:** Tab is captured in the editor with no way to move focus out.
- **Menus:**
  - Menus stay open after Tab moves focus away, and ArrowDown doesn't move into menu items.
  - The narrow-screen sidebar overlay closes only from ☰.
- **Known roadmap issue reproduced:** creating a note while viewing Trash leaves the sidebar on Trash.

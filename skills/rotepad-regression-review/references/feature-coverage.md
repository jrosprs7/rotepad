# Rotepad feature coverage map

Read this map when selecting regression checks. For a focused change, review each group for impact and execute affected groups and their neighbors. For a whole-app review, account for every supported group. This is a checklist of scenarios to assess, not a statement that all are implemented or covered automatically.

The [testing guide](../../../docs/TESTING.md) owns runnable commands and existing script coverage. The [architecture](../../../docs/ARCHITECTURE.md) owns storage and implementation facts. Inspect current controls and handlers when either inventory is stale. Future phone sync and other platforms in the roadmap are not current features to implement or certify.

## Choose combinations that can expose a missed path

Start with the user's exact sequence, then vary the boundary most likely to distinguish it from the previously passing case. For example, `Enter` at item end, `Enter` before the second word and `Enter` immediately after the marker are separate list cases. A parsed list can pass while a freshly typed prefix fails.

For shared parsing or serialization, use a synthetic mixed document containing ordinary paragraphs, inline formatting, numbered/bulleted/nested items, quotes, headings, code and a table. Inspect the affected structures after view switching and persistence. Passing each feature separately does not prove their boundaries interact correctly.

For a targeted UI change, verify command reachability, focus/selection and the changed widths/themes; do not require unrelated storage failure injection unless the change crosses that boundary. For data handling, include interruption/failure and recovery, not just the successful save path.

## Evidence and remaining gaps

Record expected outcomes before assigning status. Keep the matrix from [the skill](../SKILL.md) scoped to this run, with runtime/build identification, actual assertions or manual steps and remaining gaps. Extend existing regression scripts when they miss an affected scenario; do not imply this document itself runs tests.

Whole-app review gaps must name the feature and reason, such as unavailable physical printer or untested upgrade path. For a focused fix, group unaffected features with a reason rather than producing an inflated list of supposed passes. Update [known issues](../../../ROADMAP.md#known-workspace-issues) only from current evidence and within the user's scope.
